Versioning and releases

Releases follow Semantic Versioning. While the major version is zero, minor versions may include breaking changes; patch releases are reserved for compatible fixes. Starting at 1.0.0, breaking changes require a new major version.

The first public release is 0.1.0. Every release should update the changelog and publish corresponding GitHub release notes. Publishing a GitHub Release triggers the npm workflow for its matching v* tag; the package version and tag must match.

Release builds generate the distributable CSS, Sass package, JavaScript module, icon sprite, and third-party notices before publishing. Bulma remains a peer dependency and is not bundled into the package.
